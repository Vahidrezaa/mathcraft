# سند ۰۶ — طراحی UI/UX و سیستم طراحی «Craft» (CDS)

> **MathCraft** | سند تجربه کاربری نسخه 1.0
> مأموریت این سند: کاربر در ۱۰ ثانیه اول بگوید «این یه اپ واقعیه، نه یه پروژه دانشجویی.» جزئیات اینجا مطلق‌اند: رنگ‌ها، فاصله‌ها، انیمیشن‌ها، و رفتار پرتره/لنداسکیپ.

---

## ۱. فلسفه طراحی — «ورکشاپ دقیق»

چهار اصل، به ترتیب اولویت:

1. **محتوا پادشاه است:** کد، خروجی و نمودار، بزرگ‌ترین سطوح صفحه را می‌گیرند؛ chrome (نوارها و دکمه‌ها) حداقلی و همیشه قابل پیش‌بینی.
2. **حرکت فقط با معنا:** انیمیشن برای انتقال attention (نتیجه جدید از کجا آمد؟) و بازخورد عمل (دکمه run فشرده شد). هیچ چیز «برای زیبایی» حرکت نمی‌کند — حرکت بی‌معنا = دم‌دستی.
3. **دقت لمسی:** هر هدف لمسی ≥ ۴۸dp؛ هیچ ژستی مخفی؛ هر صفحه در دو جهت پرتره/لنداسکیپ طراحی شده، نه «کشیده‌شده».
4. **تیره پیش‌فرض، روشن شهروند درجه یک:** تم تیره حالت پیش‌فرض است (حس IDE/ابزار حرفه‌ای)، اما تم روشن با همان کیفیت طراحی شده — نه یک invert کاهنده.

## ۱.۵ استراتژی آشنایی — «اسکلت MATLAB، پوست Craft» (تصمیم D-13)

> **الهام از ArtCraft:** فرمول موفقیت مجموعه ArtCraft (PhotoCraft/LightCraft/WordCraft/...) این است: «شما از قبل بلدید» — UI آشنا = منحنی یادگیری صفر. ما همین فرمول را می‌گیریم، **اما با یک تفاوت حیاتی:** Photoshop زیباست، پس کلون پیکسلی برایشان جواب می‌دهد؛ UI متلب کهنه و کم‌کنتراست است، پس تقلید پیکسلی از آن خطاست. آشنایی ما در **لایه مفهوم** گرفته می‌شود، نه لایه پیکسل.

### سه لایه آشنایی

1. **ساختار مفهومی (مهم‌ترین):** نقشه ذهنی متلب دسکتاپ عیناً حفظ می‌شود — کاربر متلب، در MathCraft بدون آموزش «خانه» است:

| متلب دسکتاپ | MathCraft | یادداشت |
|---|---|---|
| Command Window | کنسول | همان `>>`، همان حس تایپ و جواب فوری |
| Editor | ادیتور | سلول‌های `%%` و اجرای سلولی مثل متلب |
| Workspace | متغیرها | همان ستون‌های ذهنی Name/Value/Size/Class |
| Current Folder | شیت «پوشه جاری» از نوار بالا | در موبایل تب جدا نمی‌شود (بخش ۵)؛ اما مفهوم و نام آشنا می‌ماند |
| Figures | نمودار | هر figure یک کارت در فهرست |
| Command History | شیت تاریخچه کنسول | جست‌وجوپذیر |
| Help Browser | آموزش | مرجع توابع + درس‌ها |
| Toolstrip (ریبون) | **عمداً تقلید نمی‌شود** | mobile-hostile است؛ اکشن‌ها به نوار بالا، دکمه شناور و کیبورد ریاضی منتقل شده‌اند |

2. **واژگان کلاسی:** در تور اولیه، مستندات و آموزش از اصطلاحاتی که دانشجو از کلاس متلب می‌شناسد استفاده می‌شود (پنجره فرمان، فضای کاری، پوشه جاری) و معادل هر تب در همان‌جا معرفی می‌شود — برچسب‌های کوتاه ناوبری موبایل (کنسول/ادیتور/...) دست‌نخورده می‌مانند.

3. **نشانه‌های بصری گرم (نه کپی برند):** accent کهربایی/نارنجی CDS عمداً در خانواده «حس متلب» است؛ prompt همان `>>` است؛ تم روشن با برچسب **«حالت آشنا»** عرضه می‌شود — chrome خاکستری-گرم با کیفیت مدرن، تداعی‌کننده محیط کلاس متلب اما با تایپوگرافی، کنتراست و جزئیات CDS. تم تیره **«حالت مدرن»** نام دارد. در onboarding، کاربر بین دو حالت با پیش‌نمایش زنده انتخاب می‌کند (بخش ۹).

### درس حقوقی از ماجرای ArtCraft-Adobe

کلون پیکسلی حتی از نرم‌افزار زیبا، ریسک trade dress و سؤالات اعتماد می‌سازد (ماجرای محبوبیت/حاشیه ArtCraft در مقابل Adobe). مسیر ما امن‌تر و هوشمندانه‌تر است: **پوست ۱۰۰٪ اختصاصی CDS + اسکلت مفهومی آشنا**. آشنایی به قیمت شکستن CDS به دست نمی‌آید؛ اگر بین «آشنا» و «درست» تعارض شد، «درست» برنده است.

### ۲.۳ تایپوگرافی
| نقش | فونت | وزن/اندازه |
|---|---|---|
| UI فارسی/انگلیسی | **Vazirmatn** (مجوز OFL، باندل کامل) | متن 14sp/متوسط، عنوان 18sp/بولد، عنوان بزرگ 24sp |
| کد، کنسول، اعداد | **JetBrains Mono** (OFL) | 14sp، line-height 1.5؛ ligatureها **خاموش** در کد (صحت کاراکتر مهم‌تر از زیبایی ligature است) |
| اعداد محور نمودار | JetBrains Mono | 11sp، ارقام tabular |
| LaTeX نتایج | رندر flutter_math_fork | اندازه 16sp قابل pinch |

قاعده دو زبانه: UI فارسی → Vazirmatn؛ UI انگلیسی → Vazirmatn (بخش لاتین) — یک فونت، دو زبان، بی‌ناهماهنگی. کد **همیشه** LTR با JetBrains Mono.

### ۲.۴ شعاع، فاصله، سایه
- شعاع: 8dp (المان‌های کوچک: chip، دکمه) / 14dp (کارت) / 20dp (شیت پایین).
- شبکه فاصله: 4dp؛ گاتر صفحه 16dp (پرتره) / 24dp (لنداسکیپ).
- سایه: دو سطح نرم (`0 2 8 rgba(0,0,0,.25)` و `0 8 24 rgba(0,0,0,.35)`) — نه سایه‌های خشن متریال قدیمی.
- حالت فوکوس/فشار: scale 0.98 + opacity 0.9 (هر عنصر تعاملی، بدون استثنا — این «حس زنده بودن» را می‌سازد).

### ۲.۵ آیکونوگرافی — مجموعه اختصاصی «Craft Icons» (قاعده مطلق)

> **قانون بلاک‌کننده merge:** ایموجی هرگز — در هیچ دکمه، تب، پیام، toast، مستندات یا حتی wireframe محصولی — جایگزین آیکون نمی‌شود. ایموجی مال محتوای کاربر است، نه زبان محصول. آیکون فقط از مجموعه اختصاصی Craft Icons می‌آید.

**مشخصات سیستم آیکون:**

| ویژگی | قاعده |
|---|---|
| گرید | 24dp استاندارد؛ اندازه‌های مجاز: 16/20/24/32dp — اندازه دلخواه ممنوع |
| Stroke | 1.75dp با round cap/join — هم‌وزن با تایپوگرافی Vazirmatn؛ در حالت فعال: filled |
| زبان بصری | هندسه ساده، گوشه نرم، optical balance؛ زبان «ابزار دقیق» نه «استیکر» |
| رنگ | فقط `currentColor` (ارث از توکن‌ها)؛ رنگ هاردکد در فایل SVG ممنوع (lint) |
| RTL | آیکون‌های جهت‌دار (بازگشت، ارسال، مرور بعدی) در فارسی mirror؛ آیکون‌های جهانی (run/stop، ذخیره، حذف، تنظیمات) هرگز mirror نمی‌شوند |
| پیاده‌سازی | Figma → SVG بهینه‌شده → `flutter_svg`؛ PNG آیکونی ممنوع (تار می‌شود) |
| نام‌گذاری | `ic_<domain>_<name>.svg` مثل `ic_nav_console.svg`، `ic_action_run.svg` |
| تست | snapshot golden هر آیکون در ۴ حالت (دو تم × outline/filled) — بخش CI سند ۰۸ |

**فهرست آیکون‌های سفارشی موردنیاز نسخه ۱ (~۴۵):**
- ناوبری (۵): کنسول (prompt `>_`)، ادیتور (براکت+فلش)، نمودار (منحنی+محور)، متغیرها (گرید)، آموزش (کتاب)
- اکشن‌ها: run، stop/cancel، save، share، export-PNG/PDF، copy، undo/redo، search، history، settings، folder، new-file، delete
- کیبورد ریاضی (۸): قالب ماتریس ۲×۲، براکت‌باز/بسته، صفحه‌های قالب/توابع/یونانی، Tab، Enter
- بازرس متغیرها بر اساس کلاس (۶): matrix، vector، scalar، complex، char/string، symbolic/handle
- نمودار (۶): zoom-in/out، reset، crosshair، 3d-rotate، colorbar-toggle
- وضعیت‌ها (۳): success-tick، warning، error

**قاعده هم‌وزنی:** حتی آیکون‌های «همه‌جا حاضر» مثل play/stop هم باید از همین set بازکشیده شوند؛ استفاده مستقیم از Material Icons پیش‌فرض در کنار آیکون‌های اختصاصی ممنوع است (وزن stroke متفاوت = ناهماهنگی ظریف ولی محسوس — دقیقاً همان چیزی که «دم‌دستی» حس می‌شود).

## ۴. سیاست RTL و دوزبانه بودن (تصمیم D-06)

1. chrome UI (ناوبری، منوها، متن راهنما) کاملاً RTL در فارسی — با `Directionality` سراسری و mirror درست آیکون‌های جهت‌دار.
2. **جزایر LTR همیشگی:** کنسول، ادیتور، بازرس ماتریس، محورهای نمودار، خروجی LaTeX — این‌ها داخل هر UI فارسی، LTR و چپ‌چین‌اند. جزیره = باکس با direction اختصاصی، نه متن درهم.
3. اعداد: همیشه لاتین در داده/کد/نمودار (F-11.2)؛ ارقام فارسی فقط گزینه نمایش UI (F-11.3).
4. سوییچ زبان: آنی، بدون restart؛ همه رشته‌ها از ARB files؛ هیچ رشته هاردکد اجازه merge ندارد (lint).
5. تاریخ/زمان: تقویم میلادی در UI فنی + شمسی در بخش‌های غیرفنی (تاریخچه، autosave) — جفت‌نمایش در تنظیمات.

## ۵. معماری اطلاعات و ناوبری

### ۵.۱ پرتره (Portrait) — ناوبری پایین
۵ تب، آیکون+برچسب، رنگ فعال `accent/primary` با انیمیشن انتخاب:

```
┌──────────────────────────────────────┐
│ ▪ Untitled.m           (run) (menu)   │  ← نوار بالا: فایل، اجرا، منو
├──────────────────────────────────────┤
│                                      │
│            محتوای تب فعال             │
│                                      │
├──────────────────────────────────────┤
│ [i]کنسول  [i]ادیتور  [i]نمودار  [i]متغیرها  [i]آموزش │
└──────────────────────────────────────┘
```
> `[i]` در وایرفریم‌ها = جایگاه آیکون اختصاصی CDS (بخش ۲.۵). ایموجی هرگز جایگزین آیکون نمی‌شود.

- **کنسول:** خروجی + خط ورودی چسبیده به پایین (بالای ناوبری)، کیبورد ریاضی بالای کیبورد سیستم.
- **ادیتور:** سند + gutter خطا + شماره خط؛ دکمه شناور run در گوشه پایین-چپ (LTR جزیره) همیشه در دسترس شست.
- **نمودار:** آخرین figure بزرگ + نوار فهرست figures؛ ژست‌ها: pinch-zoom، pan، double-tap reset، tap-hold crosshair.
- **متغیرها:** کارت هر متغیر (نام، شکل، کلاس، پیش‌نمایش) → تپ = نمای کامل (ماتریس مجازی‌سازی‌شده).
- **آموزش:** مرجع توابع + درس‌های مفهومی + Snippet gallery.

### ۵.۲ لنداسکیپ (Landscape) — ریل کناری و دو پنل
```
┌───┬────────────────┬─────────────────┐
│[i]│                │                 │
│[i]│   ادیتور/کنسول  │   نمودار/خروجی   │
│[i]│   (پنل فعال)    │   (پنل دوم)     │
│[i]│                │                 │
│[i]│                │                 │
└───┴────────────────┴─────────────────┘
```
- ریل ۶۴dp؛ پنل دوم: نمودار یا workspace — نسبت پیش‌فرض 55/45 با دستگیره درگ.
- قاعده طلایی لنداسکیپ: **کد و نتیجه هم‌زمان دیده شوند** — این حس «نرم‌افزار حرفه‌ای» روی موبایل افقی است؛ هرگز یک پنل تمام‌صفحه ممنوع مگر کاربر جدا کند.
- کیبورد باز در لنداسکیپ: پنل ورودی بالای کیبورد فشرده ولی قابل استفاده؛ اپ هرگز با کیبورد باز اسکرول گیج نمی‌کند (insets مدیریت دقیق).

### ۵.۳ تبلت / عرض ≥ 840dp
سه پنل (فایل‌ها + ادیتور/کنسول + نمودار/متغیرها)؛ آماده‌سازی دسکتاپ آینده (سند ۰۲ بخش ۱۱).

## ۶. کیبورد ریاضی (F-8.2 — مزیت رقابتی اصلی)

Strip ارتفاع 44dp بالای کیبورد سیستم، ۴ صفحه با swipe یا chip switcher:

| صفحه | محتوا |
|---|---|
| **پایه** | `(` `)` `[` `]` `{` `}` `,` `;` `:` `=` `^` `*` `/` `+` `-` `'` `...` Tab، ←→ |
| **قالب‌ها** | ماتریس ۲×۲، ۳×۳، بردار ستونی، `linspace(,)`، `for i=1:n … end`، `if … end`، `plot(,)`، `subplot(,,)` |
| **توابع** | `sin cos tan exp log sqrt abs sum mean inv det eig diff int solve ode45 fzero` (لمس طولانی = quick doc popover) |
| **یونانی** | `α β γ θ λ μ π σ ω φ Δ Σ ∞ ≤ ≥ ≠ ± →` (برای نام نماد CAS و کامنت) |

- کلید نگه‌داشته = حرف بزرگ/جایگزین؛ کلیک = haptic light + درج هوشمند (پرانتز باز = بسته‌شدن خودکار با cursor داخل).
- دکمه‌های همیشگی سمت راست strip: **Run** با آیکون اختصاصی (کهربایی، بزرگ‌تر) و Enter.

## ۷. مشخصات صفحات کلیدی

### ۷.۱ کنسول
- prompt `>>` با رنگ muted؛ ورودی inline ادیت‌پذیر (نه خطوط جدا).
- خروجی ماتریس: **کارت جدولی** با اسکرول افقی ظریف + fade-in ۱۵۰ms از بالا؛ ماتریس بزرگ: «۲۵×۳۵ ماتریس — مشاهده کامل» (شیت تمام‌ارتفاع با grid مجازی).
- خروجی CAS: بلوک LaTeX وسط‌چین با کارت `bg/elevated`.
- لمس طولانی روی هر خروجی: کپی (متن/کد MATLAB/latex)، ارسال به آموزش.
- history: swipe از لبه بالا نوار کنسول یا دکمه تاریخچه → شیت جست‌وجودار.
- خطا: کارت با نوار قرمز ۳dp سمت چپ، پیام زبان فعال، دکمه «مشاهده در ادیتور» (jump to line).

### ۷.۲ ادیتور
- `re_editor` + هایلایت اختصاصی ما (گرامر MATLAB: keyword توکن `accent/secondary`، رشته سبز muted، کامنت `code/comment`، عدد کهربایی روشن).
- gutter: شماره خط muted + آیکون خطا/warning؛ تپ روی آیکون = کارت خطا (سند ۰۳ بخش ۱۴).
- تحلیل زنده (F-8.3) debounce ۴۰۰ms: براکت نامتوازن، متغیر تعریف‌نشده (workspace-aware)، پیشنهاد نام تابع.
- autocomplete popup: نام‌ها + امضا + یک خط doc؛ navigation با کلیدهای کیبورد ریاضی هم کار کند.
- دکمه run شناور: 56dp، accent، هنگام اجرا → spinner با درصد progress events (سند ۰۲).

### ۷.۳ نمایشگر نمودار
- حاشیه صفر بین نمودار و صفحه — immersion؛ نوار شناور شفاف: خانه (بازگشت به فهرست figures)، ذخیره PNG، اشتراک، اطلاعات.
- **crosshair:** لمس/نگه‌داشتن → خط متقاطع + chip عددی `(x, y)` با JetBrains Mono، snap به نزدیک‌ترین نقطه سری (binary search سمت Dart).
- زوم: pinch حول مرکز pinch (نه مرکز صفحه) — جزئیاتی که MATLAB Mobile ندارد؛ pan با inertial scrolling طبیعی.
- 3D: یک انگشت = orbit (az/el با سرعت طبیعی و inertia)، pinch = zoom، دو انگشت درگ = pan؛ دکمه reset نمای اولیه.

### ۷.۴ بازرس متغیرها
- کارت: `A  3×3  double  (مختلط)` + پیش‌نمایش ۳×۳ در جدول کوچک؛ vector → sparkline کوچک.
- شیت نمای کامل: grid مجازی (۱۰k×۱۰k بدون jank با virtualization)، ویرایش سلول با تپ (commit به engine)، انتخاب ناحیه → کپی به‌صورت لفظ MATLAB.
- نوار فیلتر/جست‌وجوی نام؛ دکمه `clear` با تایید.

### ۷.۵ آموزش
- جست‌وجوی سراسری (FTS): «چطور ماتریس معکوس بگیرم؟» → مستقیم به doc `inv`.
- هر صفحه تابع: امضا، توضیح دوزبانه، ۲-۴ مثال با دکمه **اجرا در کنسول** (تزریق به کنسول با انیمیشن انتقال attention).
- درس‌های مفهومی ۵ دقیقه‌ای: اولین ماتریس، رسم زنده، ODE کاربردی، سمبلیک شیرین — هر درس تمام‌تعاملی.

## ۸. انیمیشن‌ها و بازخوردها (جدول اجباری پیاده‌سازی)

| موقعیت | انیمیشن | مدت/منحنی |
|---|---|---|
| ورود نتیجه کنسول | fade + slide 8dp از بالا | ۱۵۰ms، easeOut |
| فشردن هر دکمه | scale 0.98 | ۸۰ms |
| تب‌سوییچ | cross-fade + slide افقی 12dp در جهت ناوبری | ۲۰۰ms، emphasized |
| باز شدن شیت | slide از پایین + dim پس‌زمینه | ۲۵۰ms، cubic(0.2,0,0,1) |
| ظاهر شدن crosshair | fade سریع + chip scale از 0.9 | ۱۲۰ms |
| اجرای کد → آماده | دکمه run: morph به spinner → تیک سبز ۶۰۰ms سپس fade | — |
| خطا در gutter | ظاهر با bounce ظریف (spring) | ۲۰۰ms |
| zoom نمودار | دنبال‌کردن مستقیم انگشت (zero-lag) + inertial بعد رها | spring decay |
| تغییر تم/زبان | cross-fade ۲۵۰ms سراسری | — |
| haptic | light روی درج کلید، medium روی موفقیت اجرا، double-tap قوی برای cancel | — |

**قاعده سقف:** هیچ انیمیشنی > ۳۵۰ms؛ هیچ انیمیشنی در مسیر تایپ کد.

## ۹. حالت‌های خاص (States)

- **خالی (Empty):** هر تب اولین‌بار یک صفحه خوش‌آمد عملی دارد (نه لوگو خالی): کنسول = «۳ دستور نمونه را لمس کن»، نمودار = «اولین نمودارت با یک خط: fxplot(sin, [0 6])».
- **بارگذاری:** skeleton با shimmer ظریف (بدون spinner های چرخان نامتمرکز).
- **خطای مهلک/کرش:** صفحه احترام‌آمیز + بازیابی autosave + دکمه کپی گزارش.
- **حافظه کم:** هشدار کارت‌مانند با پیشنهاد `clear`؛ هرگز بستن بی‌اجازه متغیرها.
- **اولین اجرا (Onboarding):** ۳ گام ≤ ۱۵ ثانیه (اسکرول افقی): ۱) چه هستیم ۲) کیبورد ریاضی نشان بده ۳) انتخاب زبان + انتخاب حس با پیش‌نمایش زنده: **«حالت آشنا»** (تم روشن — تداعی محیط کلاس متلب) یا **«حالت مدرن»** (تم تیره — حس IDE) — سپس مستقیم کنسول با مثال آماده اجرا.

## ۱۰. دسترس‌پذیری (Accessibility)

- کنتراست ≥ ۴.۵:۱ همه جفت‌های متنی هر دو تم (تست خودکار golden tokens).
- Semantics کامل برای TalkBack: هر کنترل لیبل معنادار فارسی/انگلیسی؛ نمودارها توضیح متنی خلاصه («نمودار خطی، ۲ سری، بازه ۰ تا ۶»).
- Dynamic font scale تا ۱۳۰٪ بدون شکستن layout (تست اجباری هر صفحه).
- همه ژست‌ها جایگزین دکمه‌ای دارند (zoom = دکمه +/- در منوی نمودار).

## ۱۱. بودجه عملکرد UI (مکمل NFR-1 سند ۰۱)

- رندر هر فریم ≤ ۱۶ms؛ نمودار ۲D تا ۱۲k نقطه نمایشی (post-decimation) با CustomPainter بدون jank.
- جیم‌متریک صفر در تست تعامل ۱۰ دقیقه‌ای روی دستگاه مرجع (CI فلگ jank، سند ۰۸).
- باز شدن هر تب ≤ ۱ فریم scaffold + lazy data؛ بازرس ماتریس با ۱M سلول → scroll ۶۰fps (virtualization اجباری).

## ۱۲. آنچه ممنوع است (Anti-Patterns — «حس دم‌دستی» سابقاً از اینها می‌آید)

1. WebView برای هیچ بخشی از UI (تصمیم D-02).
2. رنگ‌های اشباع بی‌سیستم، سایه‌های خشن، گوشه‌های ناسازگار.
3. دیالوگ سیستم اندروید خام برای سؤالات محصول (همه دیالوگ‌ها با CDS طراحی می‌شوند).
4. لودینگ نامحدود بدون escape (cancel همیشه در دسترس است — سند ۰۲ بخش ۴).
5. ترجمه ماشینی نصفه‌نیمه؛ متن انگلیسی داخل UI فارسی (جز جزایر LTR تعریف‌شده).
6. انیمیشن‌های تزئینی روی مسیر ورودی کاربر.
7. **ایموجی به‌جای آیکون** — در دکمه، ناوبری، پیام، toast یا مستندات (بخش ۲.۵؛ گیت merge دارد).
8. ترکیب آیکون پیش‌فرض Material با آیکون‌های اختصاصی CDS (ناهماهنگی وزن stroke).
