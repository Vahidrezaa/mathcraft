## ۴. پروتکل تداوم جلسات (ضدپاک‌شدگی — الزامی، نسخه ۲ بعد از حادثه دوم)

مشکل رخ‌داده (دو بار): بازنشانی sandbox ⇒ پاک‌شدن کانتکست گفتگو، محیط (Rust/target)، **کامیتهای گیت داخل sandbox**، worklog و بسته download — همه به نقطه‌پایان جلسه قبلی برمی‌گشت.
درس حادثه دوم: **کامیت گیتِ داخل sandbox کافی نیست؛ .git هم rollback می‌شود.**

لایه‌های ماندگاری (به ترتیب اطمینان):
1. **`upload/`** — حجم خارجی، از بازنشانی جان سالم می‌برد (ثابت شد در هر دو حادثه). هر جلسه باید آخر کار یک کپی tar از وضعیت ریپو + یک آینه worklog آنجا بگذارد.
2. **دانلود توسط کاربر** — کاربر بسته آخر download را نگه می‌دارد؛ در بدترین حالت، آپلود مجدد همان فایل = بازیابی کامل.
3. گیت داخلی (برای تاریخچه درون-جلسه‌ای) + worklog.md + STATUS.md داخل ریپو.

**اقدام الزامی پایان هر جلسه:**
- `git add -A && git commit` (تاریخچه محلی)
- `tar` از ریپو → هم `download/` و هم `upload/` (نسخه پایدار)
- آینه worklog → `upload/worklog-mirror.md`
- کاربر ترغیب به دانلود بسته آخر شود.

**بازیابی جلسه جدید:** ترتیب خواندن = upload/ (جدیدترین tar) → STATUS.md → worklog.md → git log → docs/07-roadmap.md. سپس بازسازی محیط: `rustup` (بیلد اول ~2-3 دقیقه). فایل‌های تولیدی FRB regenerate می‌شوند؛ در گیت نیستند و نباید باشند.
