# سند ۰۷ — نقشه راه مایل‌استونی (Roadmap & Risk Register)

> **MathCraft** | نسخه 1.0 | مدل فازبندی: مایل‌استونی بدون تاریخ قطعی (تصمیم D-07)
> هر مایل‌استون سه چیز دارد: **محدوده (Scope)**، **تعریف اتمام (DoD)** و **دموی قابل نمایش**. اگر دمو نیست، مایل‌استون بسته نشده است — «تقریباً تمام» یعنی تمام‌نشده.

---

## ۱. نقشه کلی مسیر

```
P0 شالوده ──► P1 زبان و ماتریس ──► P2 عددی و آمار ──► P3 نمودار 2D/3D
                                                        │
                     ┌──────────────────────────────────┘
                     ▼
   P4 سمبلیک (CAS-1→2→3) ──► P5 تجربه IDE ──► P6 بتا و پایدارسازی ──► v1.0
```

پس از P1، فازهای P2 و P4-CAS1 می‌توانند **موازی** پیش بروند (تیم دوم داوطلب) — نقاط ادغام در M4.

---

## ۲. مایل‌استون‌ها

### P0 — شالوده (Foundation)
**Scope:** ریپو مونوریپو + CI پایه (fmt/clippy/test/deny + Flutter analyze) + اسکلت کرِیت‌ها + ارتباط end-to-end FRB + پوسته UI با تم CDS و ناوبری + سوییچ زبان FA/EN + طراحی مجموعه اولیه Craft Icons (ناوبری + اکشن‌های اصلی — سند ۰۶ بخش ۲.۵؛ ایموجی ممنوع) + کنسول بومی ترمینال `mc-cli` (REPL `mc` روی همان قرارداد mc-ffi — راه‌اندازی و صحت‌سنجی موتور روی Termux/دسکتاپ بدون Flutter، سند ۰۲ بخش ۲).
**DoD:**
- [ ] `evaluateLine("1+1")` از UI فارسی تا Rust و برگشت — با event streaming ساده.
- [ ] تغیین تم/زبان آنی کار می‌کند؛ CI سبز روی هر PR.
- [ ] مسیر بومی Termux: `mc --eval "1+1"` روی aarch64 بومی `ans = 2` می‌دهد و `cargo test --workspace` روی خود دستگاه سبز است (`scripts/setup-termux.sh`).
**دمو:** کنسول خالی که `1+1 = 2` را به فارسی/انگلیسی نشان می‌دهد؛ همان دمو در ترمینال با `mc`.

### P1 — زبان و ماتریس (قلب موتور)
**Scope:** mc-parser کامل (سند ۰۳ بخش‌های ۲-۱۱)، mc-interp (سمانتیک COW، کنترل جریان، توابع فایل/بی‌نام)، رجیستری توابع بخش «ریشه + ماتریسی + عنصری» (سند ۰۳ بخش ۱۲)، mc-num جبرخطی (سند ۰۴ بخش ۲-۳)، ادیتور پایه با هایلایت، فایل‌های `.m` (SAF)، خطاهای ساختاریافته FA/EN، دکمه run.
**DoD:**
- [ ] ۶۰ اسکریپت اول کورپوس (ماتریس/جبرخطی) مطابق Octave (tol 1e-9) عبور.
- [ ] `\` روی هر ۷ شاخه درخت dispatch با تست.
- [ ] خطای did-you-mean واقعی: `lenght` → پیشنهاد `length`.
- [ ] Property tests جبرخطی سبز (سند ۰۸).
**دمو:** حل یک تکلیف واقعی دستگاه معادلات ۵×۵ با نمایش گام‌ها و ردیف‌پله‌ای `rref`.

### P2 — عددی و آمار
**Scope:** `fzero, roots, integral, ode45/ode23, interp1(pchip/spline), polyfit/polyval, conv/deconv` + آمار (سند ۰۴ بخش‌های ۴-۷) + RNG/Ziggurat + progress/cancel در حلگرها.
**DoD:**
- [ ] van der Pol μ=1000 مطابق مرجع؛ انتگرال‌های تحلیلی مرجع ۱۰۰٪ در tolerance.
- [ ] `rng(42)` تکرارپذیر؛ Ziggurat goodness-of-fit سبز در CI.
- [ ] Cancel وسط ode45 → workspace consistent.
**دمو:** شبیه‌سازی آونگ با ode45 روی گوشی در < ۱ ثانیه با نوار پیشرفت.

### P3 — نمودار 2D و سپس 3D
**Scope (P3-a):** PlotSpec pipeline، `plot/scatter/bar/histogram/area/fill/polarplot/errorbar/fplot/subplot/legend/axis`، viewer تعاملی (zoom/pan/crosshair/export PNG).
**Scope (P3-b):** `plot3/surf/mesh/contour/contourf/colorbar/view`، چرخش لمسی ۶۰fps، خروجی PDF.
**DoD:**
- [ ] LTTB کیفیت تست (خطای ناحیه < ۱٪)؛ ۳ سری × ۱۰۰k نقطه ≤ ۵۰ms تا اولین فریم.
- [ ] 3D تا ۵۰k مثلث ۶۰fps روی پرچمدار مرجع؛ jank صفر در تست ۱۰ دقیقه.
- [ ] golden images رسم در CI.
**دمو:** `surf(peaks)` با چرخش روان انگشتی + crosshair روی `plot(sin(x))`.

### P4 — سمبلیک (سه زیرمایل‌استون سند ۰۵ بخش ۱۱)
**CAS-1:** حساب دقیق، simplify/expand/collect، diff کامل، subs، LaTeX.
**CAS-2:** پایپ‌لاین int کامل، solve، دستگاه خطی سمبلیک — **درگاه انتشار قابل استفاده (بدون CAS-3 هم محصول ارزش دارد).**
**CAS-3:** limit، taylor، dsolve زیرمجموعه، vpa/assume، فاکتور.
**DoD هر کدام:** مطابق جداول معیار سند ۰۵ بخش ۱۱ + خودآزمایی diff-verify فعال.
**دمو:** `int(exp(-x^2)*x^3)` با نتیجه LaTeX زیبا؛ `dsolve(D2y + y = 0)`.

### P5 — تجربه IDE حرفه‌ای
**Scope:** autocomplete + gutter تحلیل زنده، کیبورد ریاضی کامل (سند ۰۶ بخش ۶)، بازرس متغیرها، history، doc دوزبانه کامل (۲۳۰ تابع) با FTS و دکمه اجرا، `load/save` + MCWS + `.mat` خواندن، CSV، autosave بازیابی، onboarding، snippet gallery، تم روشن polish، accessibility پاس.
**DoD:**
- [ ] همه صفحات سند ۰۶ در دو جهت با dynamic font 130% تست شده.
- [ ] بازرس با ماتریس ۱M سلول روان.
- [ ] doc هر تابع رجیستری موجود و جست‌وجوپذیر.
**دمو:** یک دانشجوی مبتدی بدون هیچ راهنمایی، در ۵ دقیقه اولین نمودارش را می‌کشد (تست کاربردپذیری با ۵ نفر).

### P6 — بتا و پایدارسازی
**Scope:** کورپوس کامل ۲۰۰ اسکریپت سبز، فاز performance (بودجه‌های سند ۰۱)، فاز حافظه/باتری، crash-free ≥ ۹۹.۵٪ در ۴ هفته بتا با ۱۰۰+ کاربر واقعی، ABI split و APK ≤ ۴۵MB، توزیع GitHub Releases، صفحه About/مجوزها، آماده‌سازی F-Droid (reproducible build).
**DoD:**
- [ ] همه بودجه‌های NFR-1 پایش‌شده و سبز.
- [ ] هیچ باگ P0/P1 باز؛ feedback loop بتا فعال (کانال تلگرام/GitHub issues).
**دمو:** نصب APK از Release روی ۴ کلاس دستگاه، اجرای جریان کامل تکلیف بدون نقص.

### v1.0 — انتشار عمومی
برچسب نهایی، F-Droid ارسال، مستندات نگهداری، شروع فازبندی v1.1 (دسکتاپ Tauri-free: Flutter Desktop — از معماری آماده؛ iOS؛ FFT/سیگنال).

## ۳. ترتیب وابستگی‌های حیاتی (که اگر رعایت نشود، همه‌چیز دیر می‌شود)

1. **Golden Test harness (سند ۰۸) باید در P0 بنا شود** — نه در P6؛ صحت از روز اول اندازه‌گیری می‌شود.
2. **PlotSpec (سند ۰۴ بخش ۸) قرارداد است، نه فیچر:** mc-plot قبل از P3-a قطعی و نسخه‌دار می‌شود تا UI موازی بتواند بسازد.
3. **Error contract (سند ۰۲ بخش ۹) در P1:** UI خطاها را از روز اول ساختاریافته می‌گیرد — بازطراحی پیام‌ها در P5 = فاجعه.
4. **CAS و عددی از AST مشترک می‌خوانند** — هیچ پارسر دومی برای sym ساخته نمی‌شود.

## ۵. تعریف اتمام کلی پروژه (Global DoD — قبل از هر Release)

1. تمام تست‌ها (واحد، property، golden، UI، بنچمارک‌های آستانه‌دار) سبز در CI release.
2. بیلد reproducible از tag با lockfiles پین‌شده.
3. مستندات همگام با کد (doc هر تابع public، بدون TODO باز در مسیر کاربر).
4. APK آفلاین روی ۴ پروفایل دستگاه، هر دو جهت، هر دو زبان، هر دو تم — چک‌لیست دستی امضاشده.
5. رفتار شکست‌ها صادقانه بازبینی شده (هیچ silent wrong answer).
